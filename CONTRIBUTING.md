# Contributing to COPO Vision

First off, thank you for considering contributing to COPO Vision! It's people like you that make COPO Vision such a great tool for predictive analytics in education.

## Code of Conduct
By participating in this project, you agree to abide by the [Code of Conduct](CODE_OF_CONDUCT.md). We expect all contributors to adhere to it.

## How Can I Contribute?

### Reporting Bugs
This section guides you through submitting a bug report. Following these guidelines helps maintainers and the community understand your report, reproduce the behavior, and find related reports.
- Use the **Bug Report Template** when opening an issue.
- Explain the problem and include additional details to help maintainers reproduce the problem.

### Suggesting Enhancements
This section guides you through submitting an enhancement suggestion, including completely new features and minor improvements to existing functionality.
- Use the **Feature Request Template**.
- Provide a compelling reason why this enhancement would be useful to most users.

### Pull Requests
The process described here has several goals:
- Maintain COPO Vision's quality.
- Fix problems that are important to users.
- Enable a sustainable system for COPO Vision's maintainers to review contributions.

Please follow these steps to have your contribution considered by the maintainers:
1. Fork the repo and create your branch from `main`.
2. If you've added code that should be tested, add tests.
3. If you've changed APIs, update the documentation.
4. Ensure the test suite passes.
5. Make sure your code lints.
6. Issue that pull request!

## Local Development Setup
To set up the project locally, please refer to the `Installation Guide` section in our [README.md](README.md) for detailed backend and frontend setup instructions.

## Branching Guidelines
- `main` is the production-ready branch.
- Use `feature/<feature-name>` for new features.
- Use `bugfix/<bug-name>` for fixing issues.
- Use `hotfix/<issue-name>` for critical production patches.

## Commit Message Conventions
We follow the [Conventional Commits](https://www.conventionalcommits.org/) specification:
- `feat:` for new features
- `fix:` for bug fixes
- `docs:` for documentation changes
- `chore:` for maintenance tasks and dependency updates
- `refactor:` for code refactoring without adding features or fixing bugs
